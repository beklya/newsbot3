# Sprint 9 — База знаний инструментов (point-in-time фундамент → контекст для news-направления)

## Гипотеза (автор)

News-направление выходило монеткой (Sprint 6.3–8), **потому что новость оценивалась
в вакууме**. Если дать LLM полноценную базу знаний по инструменту — реальный
фундамент (выручка/прибыль/мультипликаторы/баланс/дивполитика), консенсус-ожидания,
живой новостной фон — LLM сможет правильно интерпретировать свежую новость
(подтверждение vs сюрприз vs противоречие) и выдать **направление, а не монетку**.

Sprint 8 эту гипотезу НЕ проверил честно: «база знаний» там была склейкой
новостных заголовков (эхо), без единой настоящей цифры. Sprint 9 строит
**настоящий фундамент** и перепроверяет.

**Конечная цель**: аналитический продукт (живое досье на тикер) → при положительном
бэктесте влить досье как context-provider в существующий Enricher/Decision
(«объединить с news-ботом, которому не хватало базы знаний»).

## Центральный инженерный вызов: point-in-time фундамент

Чтобы бэктест был честным, фундамент в досье на дату t обязан содержать только
то, что было **публично известно ≤ t** (иначе look-ahead уничтожит тест, как
hindsight-ранжирование Tavily у backtest-kit). Это разделяет источники на два слоя:

- **Историко-бэктестовый слой (point-in-time чистый)** — только для валидации:
  - **Цифры**: smart-lab квартальные финансы (структурные таблицы, историчные) —
    выручка/прибыль/EBITDA/маржа/долг по кварталам.
  - **Анкеровка во времени**: цифры квартала Q становятся «известны» на дату
    публикации отчёта (из e-disclosure material-fact / календаря отчётностей;
    дефолт при неизвестной дате — конец квартала + 60 дней, консервативно).
  - **События**: e-disclosure (решения СД, дивиденды, существенные факты) +
    ISS dividends.csv (уже есть) + новостной архив 871k (уже есть).
- **Live-слой (текущее состояние)** — только для продукта/форвардного применения,
  НЕ для бэктеста: TradingView (мультипликаторы) + smart-lab current + live-новости.

Оба слоя пишут в единую схему досье; бэктест читает только point-in-time-safe.

## Фазы

### Фаза 0 — Универс и инвентаризация данных
- Список IMOEXBC (~15) с ISS (`/statistics/engines/stock/markets/index/analytics/IMOEXBC`).
- Проверить покрытие минутными ценами (`PricesCache`); добить отсутствующих через
  `scripts/backfill_prices.py` + дневки через `fetch_pairs_and_dividends.py`-паттерн.
- Расширить новостной индекс (`dossier_lib.build_news_index`) на новые тикеры.
- Артефакт: `data/kb/universe.json` + отчёт покрытия.

### Фаза 1 — Point-in-time таймлайн фундамента (`scripts/kb_fundamentals.py`)
- Скрейп smart-lab `/q/<TICKER>/f/` (квартальные финансы) → структурный parquet
  на тикер: `{period, revenue, net_income, ebitda, margin, debt, eps, ...}`.
- Календарь публикаций: e-disclosure material-facts (дата отчёта) → `published_at`
  на каждый период; fallback +60д. → `data/kb/fundamentals/{TICKER}.parquet`
  с колонкой `known_from`.
- e-disclosure существенные факты (решения СД, дивиденды, buyback, допэмиссия) —
  timestamped события → `data/kb/events/{TICKER}.parquet`.
- Гвард: `fundamentals_asof(ticker, t)` возвращает только строки `known_from ≤ t`.
- Верификация: ручная сверка 3 тикеров (SBER/GAZP/LKOH) с известными датами отчётов.

### Фаза 2 — Генератор досье v2 (`scripts/kb_dossier.py`)
Расширяет Sprint 8 `dossier_build.py`. Новые секции на базе НАСТОЯЩИХ цифр:
1. Профиль; 2. **Финансовая таблица point-in-time** (последние ≤t кварталы:
выручка/прибыль/маржа/долг, тренд, YoY/QoQ); 3. **Мультипликаторы** (P/E, P/B,
EV/EBITDA, див.доходность — из цены ≤t и фундамента ≤t); 4. Дивиденды
(история+политика+ожидание с цифрой); 5. Риски/катализаторы; 6. Консенсус-нарратив
(из новостей + смарт-лаб); 7. **ОЖИДАНИЯ** (численные, с if_confirmed/if_broken).
- Сетка: ~15 тикеров × кварталы 2022Q3–2026Q2 (~15×16 ≈ 240 досье).
- Модель: DI Llama-70B (база) + DeepSeek-R1 (оценка), как в Sprint 8.
- Anti-look-ahead авточек дат (переиспользуем `find_lookahead_dates`).
- Чекпоинт/resume (паттерн `deepinfra_runner`). Бюджет ~$3–5.

### Фаза 3 — Live-слой (`scripts/kb_live.py`) — параллельно, для продукта
- TradingView financials-overview скрейп (Chrome MCP — JS-рендер) + smart-lab
  current → текущее досье на сегодня. НЕ участвует в бэктесте.
- Артефакт: `data/kb/live/{TICKER}.md` — готовый к показу/скармливанию в LLM.

### Фаза 4 — ВАЛИДАЦИЯ направления (ГЛАВНОЕ, `scripts/kb_evaluate.py` + `kb_backtest.py`)
Переиспользует `dossier_evaluate.py`/`dossier_backtest.py`, но контекст = **досье v2
с реальным фундаментом**. События: hard-events + Y6 impact≥0.6 по новому универсу.
- Оценка: досье v2 + свежий хвост + новость → JSON (surprise_level, direction, …).
- Бэктест: вход минута+1, горизонты 60m/240m/EOD/t1, честные кости v2.1, по годам.
- **Обязательно**: shuffle-контроль (чужое досье) + сравнение с Sprint 8 (42.5%).

**GATE (зафиксирован ДО прогона):**
- Основной (успех): genuine_surprise @лучший-горизонт **hit ≥55%** И **> shuffle на ≥5пп**
  И net после костов >0 И плюс в ≥2/3 лет И n≥40.
- Промежуточный (перспективно, оправдывает доинвест): hit 52–55% И > shuffle на ≥3пп
  И заметно > Sprint 8 (42.5%).
- Провал: ≤52% или не бьёт shuffle → база знаний направление НЕ чинит.

### Фаза 5 — Интеграция ИЛИ закрытие
- **Gate пройден** → влить досье как context-provider в Enricher (prompt получает
  свежий срез досье тикера) + Decision; обновить live-слой по крону; это и есть
  «объединение с news-ботом». Отдельный sub-план на интеграцию.
- **Gate провален** → задокументировать: даже настоящий фундаментальный контекст
  не разблокирует направление; направленная парадигма закрыта окончательно
  (с самым сильным из возможных контекстов).

## Риски (честно)
1. **Point-in-time фундамент — главный риск выполнимости.** smart-lab скрейп +
   анкеровка по датам отчётов — хрупко; e-disclosure PDF-отчётность тяжело парсить
   (поэтому цифры берём из smart-lab-таблиц, а e-disclosure — только для дат/фактов).
2. **Prior против гипотезы высокий** (~18 закрытых формулировок), НО критика
   Sprint 8 пользователем валидна — настоящий фундамент это первая по-честному
   непротестированная переменная. Тест заслуживает честного исполнения.
3. **Консенсус историчный** труднодоступен → ожидание формирует LLM из досье
   (слабее реального консенсуса; пилот меряет нижнюю границу — фиксируем в DONE).
4. **Скрейп-хрупкость** (TradingView JS/антибот) — заперта в live-слое, бэктеста
   не касается.
